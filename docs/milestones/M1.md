13 October 2026 · branch `claude/friendly-galileo-0oqqd3` · app version `0.1.0-m1`

**Status: ready for your review.** Every criterion I can check in my environment passes. Push-up counting is **logic-tested on synthetic movement only; accuracy on real people is not measured yet.** That needs your real-camera test (script at the end).

## What you can try

Install the build for your PC and the app opens to the Diagnostics screen:

- Live camera with a skeleton overlay. The arm being measured is highlighted, with its elbow angle.
- Provisional push-up counting. Every attempt is logged as counted, rejected or voided, with a plain-language reason.
- A 10-second angle trace with the top and bottom thresholds drawn on it, plus the four position checks with live values.
- Threshold sliders (bottom, top, minimum visibility, body line) that apply live and reset to defaults.
- −1 / +1 corrections, kept separate from the camera count. Keyboard shortcuts `-` and `+`.
- A Simulated input with 16 movement presets (full, slow, fast, half reps, no lockout, arm curls, sagging hips, knee push-ups, tracking loss, side flip, and more) plus a custom mode with tempo, depth, noise and dropout sliders.
- Panels for System (Windows edition, version, build, architecture, native or emulated), Camera, Pose model, and Landmarks (all 33, with visibility).
- Log export (JSON) without images, and without landmarks unless you tick the option.

## Findings (bugs caught and fixed during M1)

1. **Electron downloaded spellcheck dictionaries from Google at startup.** It happens in Electron's own process, so the CSP and my request filter couldn't see it. Only the network-log test caught it. Fixed by pointing the dictionary URL at a local non-existent path and clearing spellcheck languages.
2. **Camera permission denied showed "No camera found".** Without permission, Chromium hides device IDs, and asking for an empty ID fails with a misleading error. Fixed: empty IDs are ignored, and a missing remembered camera retries with any camera.
3. **MediaPipe needs WebGL even on the CPU path.** It uploads camera frames through WebGL; in a worker that only works if it's given a canvas. Fixed: the worker always receives one. Chromium's software WebGL (SwiftShader) is also allowed as a last-resort fallback, so a PC with a broken GPU driver can still track. Chromium labels that switch "unsafe" because it widens attack surface for untrusted web pages; Ready Up loads only its own code under a strict CSP, so I judged the trade-off worth it.
4. **Software "GPU" was 70× slower than the CPU path** (2.2 s vs about 31 ms per frame here). Fixed: software WebGL renderers are detected and skipped, and a GPU path averaging over 120 ms per frame switches to CPU once.
5. **Down-and-stay counted one rep** in the first synthetic run. Getting up made the elbow look straight before the position check had failed for its 300 ms grace period. Fixed: a rep can't start or finish while any position check is failing.
6. **Overlapping frame captures.** A new capture could start while one was in flight, wasting work. Fixed: one frame in flight at a time.

## Deviations from the approved plan

- **Minimum rep duration: 0.5 s → 0.3 s**, now defined as time spent below the top threshold. A 0.7 s push-up spends only about 0.47 s there, so 0.5 s wrongly rejected fast reps. 0.3 s (9 frames at 30 fps) still rejects single-frame glitches. Provisional, like all thresholds.
- **"In push-up position" uses the shoulder→ankle line**, not shoulder→hip. Sagging hips steepen the shoulder→hip angle and would have been misreported as "not in position" instead of "lift your hips".
- **Not in M1 (moved to M3):** automatic switch to the lite model below 15 fps (a manual Full/Lite switch exists now), and a dedicated pose recorder in Diagnostics (the export can include the last 30 s of landmarks if you tick it).
- **Bundles are not minified** in this proof of concept, to keep stack traces readable.
- **Build environment:** Wine was installed in my build container so NSIS can build the uninstaller. It doesn't affect the app.

## Your M1 test script (about 10 minutes, no recording)

1. Install the matching build (start with x64 if unsure; Diagnostics → System will say if you should use the other). At SmartScreen: **More info → Run anyway**. Launch Ready Up.
2. **System panel:** note the operating system, version, build, architecture, and whether it says "native".
3. Allow the camera; pick your webcam. **Camera** and **Pose model** panels: note camera start time, model load time, "Runs on", inference, frame-to-result and tracking rate.
4. Put the camera side-on, about hip height, 2–3 m away, with your head and whole body in view.
5. Do **5 full push-ups.** Expected: 5.
6. Do **3 half push-ups** (stop halfway). Expected: still 5; rep log says "Go a little lower".
7. Go down and **stay down 5 s**, then stand up without pushing. Expected: no count.
8. Stand side-on and do **5 arm curls.** Expected: no count; "Get into a push-up position".
9. Start a push-up and **walk out of frame** halfway. Expected: that rep voided ("lost sight of you").
10. **Unplug the webcam** while tracking, then plug it back in. Expected: "Camera disconnected", count kept, resumes.
11. Press **+1, then −1.** Expected: listed as corrections; camera count unchanged.
12. **Input → Simulated**, choose "Half reps". Expected: no counts.
13. **Export log…**, quit, relaunch. Expected: your camera is still selected.
14. Send me: the numbers from steps 2–3, actual vs expected for steps 5–12, anything confusing, and the exported log if you're comfortable (it contains no video or images).
